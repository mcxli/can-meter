# ログ形式

要件 LOG-03〜10・13・15 の実装仕様。書式は `firmware/shared/src/log_format.rs`、保存先・分割・同期の方針は `firmware/shared/src/log_policy.rs` に実装し、ホストの `cargo test` で検証している（2026-11-12時点）。SDへの書き込み（キュー・書き込みスレッド・ファイル操作・1秒ごとの同期・記録停止）は、`firmware/main/src/logger.rs` に実装した。仮データでの動作確認の結果は[段階5の検証結果](../検証結果/段階5_ログ保存.md)に記録している。

## 共通の規則

| 項目 | 内容 |
| --- | --- |
| 文字コード・改行・区切り | UTF-8（BOMなし）、改行は `\n`、区切りは `,` |
| ヘッダー | 各ファイルの先頭に、列名の行を1行置く |
| 欠損値 | 空欄で表す。`0`・`-1` 等で代用しない（取得済みの0と区別する） |
| 時刻 `t_us` | メイン機の単調増加時刻（起動からの経過時間）。単位はマイクロ秒（µs）。10進の整数 |
| 16進数 | 大文字。接頭辞（`0x`）なし |
| 引用 | `,`・`"`・改行を含む欄は `"` で囲み、中の `"` は `""` にする（補助ログの `detail` 欄のみ該当しうる） |

## 保存先とファイル名

- 起動ごとに、保存先のディレクトリ `LOG_NNNN`（NNNNは4桁の番号）を作る。番号は、SD上の既存の保存先の最大番号+1。GPSの測位や時刻に依存しない。既存のログと衝突しない。
- 仮データのログは `LOG_NNNN_DEMO`（実車のログと区別する）。番号は、仮データのものも含めて数える。
- 番号が9999を超える場合は作らない（`None`）。記録開始に失敗した扱い（記録不可の通知）になる。
- FAT（Macで、FAT32にフォーマットしたカード）に、長いファイル名で保存する。ESP-IDFのFatFsの既定は8.3形式のみのため、`CONFIG_FATFS_LFN_HEAP=y` を設定している。
- ファイルは、保存先の中に、種類ごとに10分ごと（記録開始からの経過時間）に分割する。名前は `can_001.csv`・`gps_001.csv`・`events_001.csv`（種類＋3桁の連番）。
- 分割の境界の時刻のデータは、新しいファイルだけに入る。時刻が前後して届いても、一度進んだファイルへは戻らない（二重記録・取り違えを防ぐ）。

## CANログ（`can_NNN.csv`）

ヘッダー：`t_us,id,format,kind,dlc,data`

| 列 | 内容 |
| --- | --- |
| `t_us` | メイン機の受信時刻 [µs] |
| `id` | CAN ID。標準は3桁、拡張は8桁の16進（大文字） |
| `format` | `STD`（標準）・`EXT`（拡張） |
| `kind` | `DATA`（データ）・`REMOTE`（リモート）・`ERROR`（エラーフレーム。検出できたもの） |
| `dlc` | データ長コード。受信したままの値（10進） |
| `data` | データ。16進を区切りなしで並べる。データフレーム以外とDLC 0は空 |

例：`123456,07E,STD,DATA,3,01ABFF`

全受信フレームを記録する。IDやDLCが範囲外でも、省略せず記録する（要件 LOG-04）。

## GPSログ（`gps_NNN.csv`）

ヘッダー：`t_us,utc,lat_deg,lon_deg,speed_kmh,fix_valid,time_valid,seq,session`

| 列 | 内容 |
| --- | --- |
| `t_us` | メイン機がGPSデータを受信した時刻 [µs]（測位時刻とは別） |
| `utc` | 測位UTC。`2026-11-09T12:34:56.007Z` の形。時刻が確定していなければ空 |
| `lat_deg`・`lon_deg` | 緯度・経度 [度]。小数6桁、符号つき。無効なら空 |
| `speed_kmh` | 速度 [km/h]。小数1桁。無効なら空。速度0は `0.0` |
| `fix_valid`・`time_valid` | 測位・時刻の有効性。`1`（有効）・`0`（無効） |
| `seq` | サブ機が付ける連番（欠落の検出に使う） |
| `session` | サブ機の起動ごとのセッション番号（サブ機の再起動を区別する） |

例：`9000000,2026-11-09T12:34:56.007Z,35.681236,139.767125,59.3,1,1,42,3`

## 補助ログ（`events_NNN.csv`）

ヘッダー：`t_us,event,utc,dropped,detail`

| 列 | 内容 |
| --- | --- |
| `t_us` | 発生時刻 [µs] |
| `event` | イベント名（下表。固定） |
| `utc` | `TIME_SYNC` で、`t_us` に対応するUTC。ほかは空 |
| `dropped` | 失った件数（`QUEUE_OVERFLOW` など）。ほかは空 |
| `detail` | 補足（自由な文字列。`source=DEMO` など）。引用の規則に従う |

| `event` | 意味 |
| --- | --- |
| `LOG_START` | 記録の開始。仮データのときは `detail` に `source=DEMO` を入れる |
| `LOG_STOP` | 記録の正常な停止 |
| `FILE_ROTATE` | ファイルの分割 |
| `QUEUE_OVERFLOW` | 受信キューのあふれ（`dropped` に失った件数） |
| `WRITE_ERROR` | SDへの書き込みの失敗 |
| `TIME_SYNC` | 測位UTCとメイン機の時刻の対応 |
| `GPS_FIX_ACQUIRED`・`GPS_FIX_LOST` | GPSの測位が有効・無効になった |
| `WIFI_DISCONNECTED`・`WIFI_CONNECTED` | サブ機とのWi-Fi接続の切断・回復 |
| `CAN_ERROR` | 検出できたCANの通信異常 |

## 時刻対応

- CANとGPSの受信時刻は、同じメイン機の単調増加時刻（`t_us`）で記録する。
- GPSが有効なUTCを供給したとき、`TIME_SYNC` で、測位UTCとメイン機の時刻の対応を、補助ログに追加する。
- 初回の `TIME_SYNC` までは、UTCとの対応は不明（未同期）として扱う。補正のときも、記録済みの `t_us` は書き換えず、対応を追加する。
- この対応は、通信・GPS出力の遅延を含み、厳密な同時刻観測とは扱わない。同期精度は、実測して記録する。

## 同期

- 1秒ごとに、ファイルシステムへ同期する（`SyncPolicy`：間隔 1,000,000µs）。最初の呼び出しは、基準の記録だけで、同期しない。
- 採用するAPIの同期動作（アプリ内のバッファのフラッシュで終わらず、SDへ書き出されるか）は、書き込みの実装時に確認する。
- 突然の電源断での損失が1秒以内であることは、保証しない（実機で検証する）。

## 容量の見積もり（LOG-11・未確定）

CANログは、1フレームあたり、おおよそ30〜40バイト（時刻・ID・形式・種別・DLC・データ）。2時間分の必要容量は、受信するフレームの数による。

| 仮定（未測定） | 2時間の容量 |
| --- | --- |
| 500フレーム/秒、1行40バイト | 約144MB |
| 1,000フレーム/秒、1行40バイト | 約288MB |

実車のCAN負荷（フレーム数/秒）は、段階6で測定してから、LOG-11 に反映する。SDカードは、MacでFAT32にフォーマットして使う（[段階2の記録](../検証結果/段階2_メイン機の基本動作.md)）。FAT32のファイルは、1つあたり4GB未満にする必要があるが、10分ごとに分割するため、通常は超えない。
