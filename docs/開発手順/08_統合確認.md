# 8. 全機能の統合確認

## 目的・対応要件

CAN受信・表示・GPS・Wi-Fi・SD保存の同時動作を評価し、要件の達成状況を記録する。
対応：TEST-01〜10、NFR-01〜06。
前提：段階7までの個別確認が完了していること。

## 試験準備

1. ファームウェアの版・ビルド設定・依存関係を固定する。
2. 採用信号、タイムアウト、カード容量・形式、ログ形式を記録する。
3. 実車で観測したフレームレート・ID分布・バーストを整理し、試験負荷を決める。
4. 2時間の継続試験は、可能であれば記録ログのベンチ再生を使う。受信専用メーターを、車両への送信装置として使わない。
5. 電源断試験用のSDは必要な内容をバックアップし、他のデータから分ける。

| TEST-06 | ログ取り出し・PC読み出し | CSVの形式・件数・時刻対応を確認し同期精度を記録 |

## 性能測定

- CAN受信時刻、描画要求時刻、画面反映の観測方法を記録し、200ms目標を評価する。内部処理時間だけを画面反映時間として扱わない。
- 更新周期と新規データの到着周期を分ける。元のCAN信号が低頻度な場合、毎秒10回の表示処理が毎秒10回の新規値取得を意味するわけではない。
- 受信件数、キュー最大使用量、キューあふれ、書き込み時間、書き込み失敗、再起動理由を記録する。
- 比較用の送信件数・基準ログがある場合は照合する。キューあふれゼロだけで無欠落とは結論付けない。
- メモリー使用量の推移と10分ごとのファイル分割を、2時間試験全体で確認する。

## 障害時の確認

1. Wi-Fiを切断し、CAN表示・記録の継続と自動再接続を確認する。
2. GPSの更新を停止し、無効表示へ遷移してもCAN処理が継続することを確認する。
3. SD未挿入・検証用の容量不足・書き込みエラーを確認する。実装でエラーを注入する方法も利用し、受信・画面が継続することを確認する。
4. 記録停止ボタンで正常終了し、残りのバッファとファイル末尾を照合する。
5. 検証用カードで突然の電源断を試し、最終読出可能時刻・損失行・CSV/ファイルシステム破損を記録する。1秒同期だけで最大損失を保証しない。

## 未確定事項の評価

自動終了は[自動終了と電源断対策](09_自動終了と電源断対策.md)の検証項目を実施する。通常のOFFでは保存後の遮断を確認し、保持不能の強制断では損失・破損状況を評価する。

| 要件 | 実測・決定する内容 |
| --- | --- |
| LOG-11 | 保存速度から必要容量を計算し、2時間試験で容量・形式を評価 |
| NFR-04 | 電源投入から画面・受信・記録開始までを個別に測定し、許容時間を決定 |
| NFR-06 | 電源OFFの定義・給電構成を明記し、必要な状態の消費電力を測定して許容値を決定 |

## 結果の記録・完了条件

各試験について、条件・期待値・実測値・合否・証拠ログ・未確認点を保存する。

- [ ] 受け入れ項目に対する結果が揃っている。
- [ ] 性能目標未達や未確認項目を、合格として処理していない。
- [ ] 問題を修正した場合は、影響する試験を再実施した。
- [ ] 実装仕様と要件定義書の内容が一致している。
