# 9. 自動終了と電源断対策

## 目的・対応要件

ACC／IGのOFFまたは外部電源の低下を検知し、ログを正常終了してから給電を停止する。通常利用で記録停止ボタンの操作を不要にする。
対応：LOG-10・13・16、PWR-01〜06、NFR-06、TEST-09。
本書は実装方針であり、回路・保持時間・実機動作は未検証。メイン機・サブ機の選定は変更しないが、自動終了には停止検知と電源保持・遮断の構成が別途必要となる。

## 構成方針

```text
車両の電源 ── 保護・電源保持・給電制御 ── メイン機とSD
                         ▲                 │
                         └── 終了完了通知 ──┘
ACC／IG または保持回路より手前の電源監視 ── 停止検知入力
```

- ACC／IGを使う場合は、機器の入力仕様に適合する検知回路を経由する。車両電圧をESP32のGPIOへ直接入力しない。
- 常時電源からの遅延遮断、または補助電源による保持など、実機に合う方式を選ぶ。停止通知だけでは、電源断後の書き込み時間を確保できない。
- 外部電源低下は保持回路より手前で監視し、保持後の電源が落ちてから検出する構成にしない。
- USBを含む複数電源の同時接続時も、逆給電・切り替え・遮断条件を確認する。
- サブ機のGPSはメイン機の終了待ち条件にしない。サブ機が先に停止しても、メイン機とSDの保存を完了できる構成にする。
- 基板の電池接続や電源制御機能が利用できるかは回路図と実機で確認する。電池を付けただけで検知・保持・自動遮断が成立したとは扱わない。

## 終了の検知条件

| 入力・状態 | 扱い |
| --- | --- |
| ACC／IGのOFF | 安定してOFFになったことを確認し、自動終了を要求する |
| 外部電源低下 | 保持可能な時間内に終了できるよう、早期に終了を要求する |
| エンジン回転数0のみ | 終了条件にしない |
| CAN未受信・Wi-Fi切断のみ | 通信状態として扱い、給電停止条件にしない |
| 手動の記録停止 | 同じ保存処理を使用するが、給電停止は要求しない |

検知電圧、チャタリング除去時間、ヒステリシス、再始動時の一時的な電圧低下の扱いは実測に基づき設定する。低下の猶予が短い場合は、通常のOFF判定より早く保存処理へ移る。

## 状態遷移と処理

| 状態 | 実行内容 |
| --- | --- |
| 通常動作 | 受信・表示・記録を継続し、停止入力を監視する |
| 終了要求 | 要求を1回だけ受理し、原因と単調増加時刻を保持する |
| 保存処理 | 新しいログ投入を止め、受理済みキューを排出して同期・ファイル終了を実行する |
| 終了完了 | 同期・クローズの成功後に、給電制御へ終了完了を通知する |
| 保存失敗 | エラーを保持し、正常終了とは区別する。残り時間内でのみ再試行する |
| 給電停止 | 給電制御がメイン機・必要な周辺回路の給電を停止する |

処理順序：

1. 停止入力を受け、記録開始やファイル分割の処理と競合しないよう終了要求をまとめる。
2. 受信処理から新しいログをキューへ投入するのを停止する。保存対象の終端を確定し、以降の受信データを保存済みと扱わない。
3. 画面の輝度低下や不要な通信停止など、保存を妨げない範囲で消費電力を減らす。
4. 受理済みのCAN・GPS・補助ログを保存する。終了原因と対象ログの終端情報も可能な範囲で残す。
5. ファイルシステムへ同期し、全ログを閉じる。使用APIに応じてアンマウント等の必要な終了処理を行う。
6. 全処理の成功後に終了完了を通知し、給電制御側で遮断する。ソフトウェアのスリープと物理的な給電停止を区別する。

手動の記録停止は保存処理までを共用し、成功後も受信・表示を継続する。自動終了では給電停止へ進む。手動停止済みでも自動終了要求を受けたら給電停止まで進める。

一度保存処理に入った後は途中で記録へ戻さない。保存完了までにACC／IGがONへ戻った場合は、電源が安定していることを確認してから、新しい記録セッションを開始する。低電圧が続く場合は再開しない。

## 保持時間・失敗時の設計

必要保持時間は、検知遅延＋処理移行時間＋最大キューの書き出し＋SD同期・クローズ時間＋余裕で決める。固定の秒数を先に保証せず、使用カード・負荷・電源状態を変えて測定する。

電源制御側には最大保持時間を設け、ソフトウェア停止やSDハングで常時給電が続かないようにする。最大時間で遮断した場合は正常終了の保証対象外とし、次回起動でログを確認する。保持不足・補助電源の消耗等で保存に失敗する可能性は残る。

通常時の1秒同期と10分ファイル分割も継続する。これらだけで突発的な断線や保持不能時のデータ損失・SD破損を完全に防げるとは扱わない。

## 実装手順

1. 給電経路、停止検知入力、保持・遮断方式、終了完了通知方法を接続仕様へ記載する。
2. ベンチ環境で停止入力を模擬し、手動停止と共用する終了処理を実装する。
3. ログ書き込みとファイル分割の途中、SD未挿入・容量不足・書き込み失敗中にも終了を要求する。
4. 電源保持を組み合わせ、停止検知から保存完了までの時間と電圧を測定する。
5. 実測結果に余裕を加えて保持時間を選定し、最大保持時間とOFF後の消費電力を設定する。
6. ACC／IGの復帰・連続ON/OFF・再始動を確認した後に、車両の給電構成で検証する。

## 検証・完了条件

- [ ] 手動操作なしで、停止検知・保存完了・給電停止の順になる。
- [ ] 回転数0や通信断だけでは終了しない。
- [ ] 終了要求の重複や10分分割との競合で、二重クローズ・再記録が発生しない。
- [ ] 保存完了までメイン機とSDが動作可能な電圧を維持する。
- [ ] 正常終了時は、終了要求前に受理した保存対象とCSVの件数・末尾が一致する。
- [ ] SD異常や保持不足時は正常終了と誤判定せず、最大保持時間で遮断できる。
- [ ] 終了中の再ON・再始動を確認し、旧セッション破損や再起動ループがない。
- [ ] 手動記録停止では給電を停止せず、受信・表示を継続する。
- [ ] OFF後の消費電力を実測し、NFR-06の許容値を決定する。

試験結果は[統合確認](08_統合確認.md)の結果と合わせて残す。試験に使用するログ・カードはバックアップし、通常OFFと保持不能による強制断を分けて評価する。
