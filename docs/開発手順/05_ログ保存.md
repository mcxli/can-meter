# 5. CSVログ保存と時刻管理

## 目的・対応要件

仮CANデータと実GPSを保存し、記録開始・分割・停止・読み出しを確認する。
対応：LOG-01〜16、NFR-05、TEST-06・08・09。
前提：段階2のSD読み書き、段階4のGPS受信が動作すること。

## 保存形式の実装案

| ファイル | 主な列 |
| --- | --- |
| can_連番.csv | メイン機受信時刻（単調増加、µs）、CAN ID、標準/拡張、フレーム種別、DLC、データ |
| gps_連番.csv | メイン機受信時刻（µs）、測位UTC、緯度、経度、速度、各有効性、サブ機セッション、連番 |
| events_連番.csv | 発生時刻、イベント種別、時刻対応情報、欠落数、エラー情報 |

文字コード・列順・単位・欠損値表現を固定し、ヘッダーと仕様に残す。CAN ID・データの16進数表記規則も統一する。仮データのログには実車ログと区別する情報を残す。

## 作業手順

1. 起動ごとに一意な保存先を作る。GPS未測位でも作成でき、既存ログと衝突しない識別方法にする。
2. SD初期化完了後に自動記録を開始する。表示画面やGPS測位完了を開始条件にしない。
3. 受信・描画からSD書き込みを分離し、有限長のキュー・バッファを用いる。SD遅延で受信処理を長時間待たせない。
4. CAN・GPS・補助情報をCSVに書き、1秒ごとにファイルシステムへの同期処理を行う。単なるアプリ内バッファのフラッシュで終わらないよう、採用APIの同期動作を確認する。
5. 10分ごとにファイルを閉じて次のファイルへ移る。境界で受信したデータが二重記録・欠落しないか確認する。
6. 記録停止ボタンで新規記録を停止し、残りのバッファを書き出してファイルを閉じる。成功後に電源断可能と表示する。
7. 停止処理が失敗した場合はエラーを表示し、正常終了した扱いにしない。受信・表示は継続する。
8. SDをMacへ移し、CSVの列・件数・時刻・末尾行を確認する。

## 時刻対応

- CAN・GPSの受信時刻は、同じメイン機の単調増加時刻で記録する。
- GPSが有効なUTCを供給した際に、測位UTCとメイン機受信時刻の対応を補助ログへ残す。
- これは通信・GPS出力の遅延を含む時刻対応であり、厳密な同時刻観測とは扱わない。
- 初回対応前は未同期とし、補正時も過去の単調増加時刻を書き換えない。
- 測位UTCを持つGPS点とCANの対応精度を測定する。基準が足りない場合、評価可能な範囲と未評価部分を記す。

## 異常時の動作

| 条件 | 動作 |
| --- | --- |
| SD未挿入・初期化失敗 | 記録不可を表示し、受信・画面は継続 |
| 容量不足・書き込み失敗 | 記録停止を表示し、既存ログを上書きしない |
| キューあふれ | 検出件数を保持し、記録可能なら補助ログへ保存 |
| GPS未測位・Wi-Fi切断 | CAN記録を継続し、状態変化を記録 |
| 突然の電源断 | 再起動後に読み出し可否・末尾・破損を評価 |

SDへの書き込み自体が不可能な場合、エラーは画面・取得可能なデバッグログで確認する。電源断試験にはバックアップ済みの検証用カードを使う。

## 成果物・完了条件

- [ ] CSV仕様、保存先の命名規則、時刻対応方法を文書化した。
- [ ] 自動開始・10分分割・正常停止・Mac読み出しを確認した。
- [ ] 1秒同期を実装し、突然の電源断での損失が1秒以内とは保証していない。
- [ ] 記録量から2時間分の必要容量と余裕を算出し、LOG-11へ反映した。

## 自動終了との共通化

記録停止の保存処理は、ACC／IGのOFF・外部電源低下による自動終了と共通化する。手動停止では受信・表示を継続し、自動終了では保存成功後に給電停止へ進む。
電源保持の構成を含む詳細は[自動終了と電源断対策](09_自動終了と電源断対策.md)を参照する。1秒同期だけで自動終了できるとは扱わない。
