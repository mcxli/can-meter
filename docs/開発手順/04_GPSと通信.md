# 4. GPS取得とWi-Fi通信

## 目的・対応要件

ATOM S3 Liteで取得したGPS情報を、メイン機へ1Hzを初期周期として送信する。
対応：GPS-01〜06、NET-01〜05、UI-06、TEST-05。
前提：段階1の両機の書き込みが完了し、段階3のGPS表示先があること。

## 作業手順

1. 採用済みGPSユニットの公式資料から通信方式・電源・端子・通信速度を確認し、接続表へ記録する。端子の色だけで割り当てを判断しない。
2. サブ機でGPSの出力を読み取り、解析前のデータを確認する。GPSの実際の出力形式に対応する処理を使用する。
3. 速度・緯度・経度・UTCを取得する。位置と時刻の有効性を別々に管理し、同一測位結果の項目を組み合わせる。
4. 単位をkm/h・十進度へ統一する。GPSの元の単位から変換した箇所を記録する。
5. メイン機にWi-Fi AP、サブ機にSTAを実装する。SSID・認証設定・UDPポートを設定として管理する。
6. 新しいGPSデータをUDPのJSONメッセージで送信する。メイン機は受信直後に自身の単調増加時刻を付ける。
7. 型・長さ・範囲・形式の不正なメッセージは状態を記録して破棄し、表示や記録処理を停止させない。
8. Wi-Fi切断時の自動再接続と、サブ機再起動時の識別を実装する。過去データの再送は行わない。

## 通信形式の実装案

| 項目 | 内容 |
| --- | --- |
| version | メッセージ形式の版 |
| session_id | サブ機の起動ごとに変わる識別子 |
| seq | セッション内の連番 |
| fix_utc | 測位に対応するUTC。時刻無効時はnull |
| position_valid / time_valid | 位置と時刻の有効性 |
| latitude_deg / longitude_deg | 十進度。無効時はnull |
| speed_kmh | GPS速度。無効時はnull |

欠落・重複・順序逆転はセッション識別子と連番の組で判定する。遅着データで最新値を上書きしない。連番欠落は原因をWi-Fiに断定せず、検出事実として記録する。

## 測位・更新停止の確認

- 測位可能な場所で、位置・速度・時刻を確認する。
- 未測位でも接続状態と測位状態を区別して表示する。
- サブ機停止・GPS出力停止・Wi-Fi切断を分けて試す。
- タイムアウト値は実際の出力周期と遅延を見て設定し、仕様に残す。
- メイン機はGPS測位時刻と受信時刻を区別する。両者の差だけで時計のずれや片道遅延を確定できるとは扱わない。
