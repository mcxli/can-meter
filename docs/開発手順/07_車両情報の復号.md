# 7. 車両情報の復号と実データ表示

## 目的・対応要件

生CANログから車両情報を復号し、仮データの表示を実データへ置き換える。
対応：CAN-02・03・06〜08、SIG-01〜08、TEST-03。
前提：[段階6](06_実車CAN受信.md)で対象車両の生ログが取得できること。

## 実装順

1. 回転数・CAN車速。
2. 水温・油温。
3. アクセルペダル開度・ブレーキON/OFF。
4. ステアリング舵角。
5. ギアポジション。CAN直接値を確認し、取得できない場合は回転数・CAN車速から前進ギアを推定する。

ギアポジション以外は、受信だけで取得できない項目を未対応とする。公開資料の世代・対象車両を確認し、初代と2代目の定義を混在させない。

ギア推定では実車ログで各ギアの回転数と車速の比を確認し、判定範囲・安定判定時間・低速時の無効条件を定める。画面ラベルは「ギア」とし、取得方法は内部仕様で区別する。停車中・クラッチ操作中・信号不整合時などは「--」とする。N・Rを推定だけで確定しない。判定不能条件を十分に検出できない場合は推定機能を未対応とし、値を表示しない。

## 作業手順

1. 公開資料・実装例から候補のIDと換算式を集め、URL・参照した版・対象仕様を記録する。
2. 対象IDが実車ログに存在するか確認する。IDの存在だけで、その値の意味が確定したと扱わない。
3. ログ再生またはオフライン解析で、ビット位置・長さ・バイト順・符号・換算式を確認する。
4. 各項目について照合方法と許容誤差を先に設定する。比較元の丸め・更新周期・時刻差も考慮する。
5. 車両状態や照合可能な表示と比較する。独立した基準がない項目は、その制約を記録し「精度確認済み」とはしない。
6. 復号結果を段階3の共通データ構造へ渡し、表示とCAN生ログ保存が独立して動くことを確認する。
7. 短いDLC、未対応ID、境界値、無効値、更新停止時の扱いを確認する。
8. 仮データ供給を通常動作から外す。開発用に残す場合は明示的な設定と識別表示を付ける。

## 解析仕様の記録項目

| 項目 | 内容 |
| --- | --- |
| 信号 | 名称、意味、表示先 |
| フレーム | ID、標準/拡張、必要DLC |
| ビット定義 | 開始位置、長さ、ビット番号規則、バイト順、符号 |
| 変換 | 係数、オフセット、換算式、単位 |
| 有効性 | 無効値、許容範囲、タイムアウト |
| 根拠 | 公開資料の出典・版、使用ログ |
| 判定 | 照合条件、許容誤差、結果、未確認範囲 |

車速はGPS速度と名称を分ける。GPSと一致しないことだけでCAN復号の誤りとは判断しない。アクセルはペダル開度、ブレーキはON/OFFという採用方針を維持する。

## 検証方法

- 保存済みログを使い、車両に接続せず同じ結果を再現できるようにする。
- 復号関数は既知の入力・期待値で確認する。特に符号、バイト順、DLC不足を確認する。
- 画面には採用できた値だけを表示し、未取得・未対応は「--」とする。
- 検証用の車両操作・画面操作は停車中に行う。走行データが必要な場合は記録後に解析する。

## 成果物・完了条件

- [ ] 各候補について取得可否と採用・未対応の判定を残した。
- [ ] 採用信号の解析仕様、照合結果、再生用ログがある。
- [ ] 実データと無効値処理が4画面へ反映される。
- [ ] 生ログは復号の成否と関係なく保存される。
