# CANメーター自作プロジェクト 要件定義書

## 1. 目的

スバル BRZ（ZC6）のCANデータとGPS情報を取得し、車両情報をリアルタイム表示するとともに、走行後の分析用ログを保存する。

## 2. 要件の状態

- **採用**：本プロジェクトで採用した方針・機能。性能の初期目標は実機で検証・調整する。
- **候補**：実装対象の候補。取得可否は実車で確認する。
- **要決定**：検証結果を踏まえ、追加で具体化する項目。現時点では確定仕様に含めない。

## 3. 対象車両

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| メーカー・車種 | スバル BRZ | 採用 |
| 車両型式 | ZC6 | 採用 |
| 年式 | 2014年式 | 採用 |
| トランスミッション | MT（マニュアル） | 採用 |
| ECUの変更・書き換え有無 | 純正（ノーマル）、変更・書き換えなし | 採用 |

## 4. システム構成

```text
車両のOBD2端子
    │ CAN（受信専用）
    ▼
メイン機：Waveshare ESP32-S3 4.3B
    ├── LVGLによるメーター表示
    └── Micro SDカードへのログ保存
    ▲
    │ Wi-Fi
サブ機：M5Stack ATOM S3 Lite
    ▲
    │ ケーブル接続
M5Stack GPSユニット
```

## 6. 機能要件

### 6.1. CANデータ取得・解析

| ID | 要件 | 状態 |
| --- | --- | --- |
| CAN-01 | 車両のOBD2端子からCANフレームを取得する | 採用 |
| CAN-02 | 取得したCANフレームを解析し、表示用の車両情報に変換する | 採用 |
| CAN-03 | ZC6向けに公開されたCAN情報を調査し、解析仕様の参考とする | 採用 |
| CAN-04 | CAN通信はListen-onlyモードによる受信専用とし、データフレーム、診断要求、ACK、エラーフレームを送信しない | 採用 |
| CAN-05 | 全受信フレームを記録対象とし、表示IDで受信を制限しない。通信速度・フレーム形式は公開情報と実車ログに基づいて設定する | 採用 |
| CAN-06 | 項目ごとにCAN ID、ビット位置、長さ、バイト順、符号、換算式、単位、出典を実装時に文書化する | 採用 |
| CAN-07 | 公開情報の復号結果を実車ログと車両状態・照合可能な表示値で確認し、適用できる項目を採用する | 採用 |
| CAN-08 | 未受信・異常値・更新停止は無効値として扱い、画面には「--」を表示する。項目ごとの範囲・タイムアウトは実装時に設定する | 採用 |

表示・記録する車両情報は、車両が送出するCANフレームを受信するだけで取得できる項目を対象とする。診断要求の送信が必要な項目は対象外とし、各候補の取得可否は実車で確認する。

### 6.2. 車両情報の表示候補

以下の8項目を候補として残す。初期実装は回転数・車速・水温・油温を優先する。ギアポジションは受信した信号からの推定も対象とする。それ以外の項目は受信のみで取得できない場合に未対応とし、診断要求を送信して補わない。

| ID | 項目 | 定義・確認事項 | 状態 |
| --- | --- | --- | --- |
| SIG-01 | エンジン回転数（RPM） | 優先実装。単位はrpm | 候補 |
| SIG-02 | 水温 | 優先実装。単位は℃ | 候補 |
| SIG-03 | 油温 | 優先実装。単位は℃ | 候補 |
| SIG-04 | アクセル開度 | アクセルペダル開度を対象とし、単位は% | 候補 |
| SIG-05 | ブレーキ | 初期実装はON/OFF | 候補 |
| SIG-06 | 車速 | 優先実装。単位はkm/h。CAN由来としてGPS速度と区別する | 候補 |
| SIG-07 | ステアリング舵角 | 左右の符号を含む角度（°）。符号と基準位置は実車で確認し文書化する | 候補 |
| SIG-08 | ギアポジション | CANの直接受信可否を確認する。直接取得できない場合は受信した回転数・車速から前進ギアを推定する。画面ラベルは「ギア」とし、「推定」は表示しない。取得方法は内部仕様で区別する。停車中・クラッチ操作中など推定条件を満たさない場合は「--」とし、推定だけでN・Rを確定しない | 候補 |

### 6.3. 画面表示

| ID | 要件 | 状態 |
| --- | --- | --- |
| UI-01 | メイン機の画面に車両情報をメーターとしてリアルタイム表示する | 採用 |
| UI-02 | 画面描画にLVGLを使用する | 採用 |
| UI-03 | 総合・温度重視・レース・GPSの4画面を用意する。細かな配置と表示範囲は実装時に調整する | 採用 |
| UI-04 | 車両情報は毎秒10回更新し、CAN受信から表示まで200ms以内を初期目標とする。GPSは新しい測位結果の受信時に更新する | 採用 |
| UI-05 | 無効な値は「--」とし、CAN未受信、GPS未測位、Wi-Fi切断、ログ保存異常を状態表示する | 採用 |
| UI-06 | GPS画面にGPS速度・位置・時刻を表示する。画面の時刻は日本時間とする | 採用 |
| UI-07 | タッチボタンで画面を切り替える。画面切り替え中もCAN受信・GPS受信・ログ保存を継続する | 採用 |
| UI-08 | 総合・レース画面のギア数字は通常時に白で点灯し、有効なエンジン回転数が発動値以上になると、明るい赤・暗い赤を交互に表示して点滅させる。数字は完全に消さない | 採用 |
| UI-09 | 通知の発動回転数・解除回転数・点滅周期を設定可能とする。解除値は発動値より低くし、回転数が解除値以下で通常表示へ戻す。初期値は実装時に決定する | 採用 |
| UI-10 | ギア判定不能時は「--」をグレーで表示し、点滅より優先する。回転数が無効・更新停止の場合は通知状態を解除する。両画面で同一の通知状態と点滅位相を共有し、受信・記録を妨げない | 採用 |

| 画面 | 主な表示内容 |
| --- | --- |
| 総合 | 回転数・CAN車速・水温・油温・ギアポジション・アクセルペダル開度 |
| 温度重視 | 水温・油温を大きく表示 |
| レース | 横長の回転数バー、回転数、ギアを大きく表示し、CAN車速・水温・油温を併記 |
| GPS | GPS速度・位置・時刻 |

レース画面は視認性を重視し、ギア・回転数・車速を中心に配置する。操作画面は設けない。ブレーキ・舵角は取得候補として残すが、初期画面には表示せず、全受信CANフレームの記録は継続する。回転数バーの色分けはデザイン表現とし、警告閾値を確定するものではない。

### 6.4. GPS情報取得

| ID | 要件 | 状態 |
| --- | --- | --- |
| GPS-01 | サブ機でGPSユニットから情報を取得する | 採用 |
| GPS-02 | GPS速度を取得する | 採用 |
| GPS-03 | 位置情報を取得する | 採用 |
| GPS-04 | 時刻情報を取得する | 採用 |
| GPS-05 | 初期取得周期は1Hzとし、ユニットの対応範囲で変更可能とする。速度はkm/h、位置は緯度・経度の十進度、時刻はUTCとして扱う | 採用 |
| GPS-06 | GPS出力に基づいて測位・時刻それぞれの有効性を判定する。未測位・更新停止時は状態を表示・記録し、CAN処理は継続する。タイムアウトは実装時に設定する | 採用 |

### 6.5. メイン機・サブ機間通信

| ID | 要件 | 状態 |
| --- | --- | --- |
| NET-01 | サブ機からメイン機へWi-Fi経由でGPS速度・位置・時刻を送信する | 採用 |
| NET-02 | メイン機をAP、サブ機をSTAとし、外部ルーターを使用しない。接続設定は実装時に構成する | 採用 |
| NET-03 | UDP＋JSONを使用する。新しいGPSデータの取得ごとに送信し、連番・測位時刻・速度・位置・測位と時刻の有効性を含める。初期周期は1Hzとする | 採用 |
| NET-04 | 切断時は自動再接続する。連番で欠落を検出・記録し、重複・順序逆転したデータで最新表示を上書きしない。再起動時の連番リセットを識別できる形式とする | 採用 |
| NET-05 | 初期実装では通信断中の過去データを再送しない。通信断中もCAN表示・CAN記録を継続する | 採用 |

### 6.6. ログ保存

| ID | 要件 | 状態 |
| --- | --- | --- |
| LOG-01 | 受信した生CANデータをMicro SDカードに自動保存する | 採用 |
| LOG-02 | GPSログをMicro SDカードに自動保存する | 採用 |
| LOG-03 | 保存したログを走行後の分析に利用できる形式とする | 採用 |
| LOG-04 | 表示対象に限定せず、全受信CANフレームを記録する | 採用 |
| LOG-05 | CANログにメイン機の受信時刻、ID、フレーム形式、DLC、データを記録する | 採用 |
| LOG-06 | GPSログに測位時刻、メイン機の受信時刻、緯度、経度、速度、測位・時刻の有効性、連番を記録する | 採用 |
| LOG-07 | CAN・GPSの受信時刻はメイン機の単調増加時刻で記録し、GPSのUTCとの対応関係を別途保存する。測位時刻と受信時刻を区別し、同期精度は実測する | 採用 |
| LOG-08 | GPS時刻確定前からCANを記録する。UTCとの対応が不明な間は未同期として扱う。時刻補正時も記録済みの単調増加時刻は変更せず、対応関係を追加する | 採用 |
| LOG-09 | 初期形式はCAN・GPS別のCSVとする。起動ごとに一意な保存先を作り、10分ごとにファイルを分割する。命名規則は実装時に文書化する | 採用 |
| LOG-10 | SD初期化完了後に自動記録を開始し、GPS測位を待たない。「記録停止」ボタンでバッファの保存とファイル終了を完了し、電源断可能な状態を表示する | 採用 |
| LOG-11 | SDカードの容量・ファイルシステム・必要な連続記録時間を確定する | 要決定 |
| LOG-12 | SD未挿入・容量不足・書き込み失敗時は記録不可または記録停止を通知し、受信とメーター表示を継続する。容量不足時も既存ログを上書きしない | 採用 |
| LOG-13 | 1秒ごとにファイルシステムへの同期処理を行う。突然の電源断による損失量・破損状況は実機で検証し、損失が1秒以内であることは保証しない | 採用 |
| LOG-14 | 記録停止・電源OFF後にSDカードを取り出し、PCへコピーする。CSVを読める表計算ソフト等で分析可能とする | 採用 |
| LOG-15 | 受信キューあふれ、検出できた通信欠落、書き込み失敗、時刻対応関係を補助ログに記録する。SDに記録できない異常は画面に通知する | 採用 |
| LOG-16 | ACC／IGのOFFまたは外部電源低下を検知し、新規ログ投入停止・残データ保存・同期・ファイル終了を自動実行する。成功後に給電停止を要求する。手動記録停止も残す | 採用 |

### 6.7. 自動終了・電源保持

| ID | 要件 | 状態 |
| --- | --- | --- |
| PWR-01 | 停止検知と、メイン機・SDが保存を完了するまでの電源保持・完了後の給電停止を組み合わせる。ソフトウェアのみでの電源断対策とはしない | 採用 |
| PWR-02 | エンジン回転数0・CAN未受信・Wi-Fi切断のみでは自動終了しない | 採用 |
| PWR-03 | 保持時間は検知から最大保存時間までを実測し、余裕を加えて決定する。最大保持時間を設け、保存失敗・ハング時の常時給電を防ぐ | 採用 |
| PWR-04 | 同期・ファイル終了の成功後に終了完了を通知する。失敗・時間切れは正常終了と区別する | 採用 |
| PWR-05 | 手動記録停止は給電停止を伴わず、受信・表示を継続する。自動終了要求時は手動停止済みでも給電停止へ進む | 採用 |
| PWR-06 | 検知入力・保持・遮断回路、保持時間、再ON時の処理を実装時に確定し、通常OFFと保持不能による強制断を分けて検証する | 採用 |

実装方針は[自動終了と電源断対策](09_自動終了と電源断対策.md)を参照する。採用機器は維持し、必要な電源周辺構成は実装時に確認する。

## 10. 実装・実機検証で具体化する事項

表示・通信・ログ・開発環境の初期方針は上記を採用する。以下は実装・実機検証の中で具体化する。

1. CAN通信設定、各候補の取得可否、ID・換算式、照合方法・許容誤差。
2. 各画面の詳細配置・表示範囲と、CAN・GPS・Wi-Fiのタイムアウト。
