# 1. Macでの開発環境構築

## 目的・対応要件

Macで両機のC++コードをビルドし、USBで書き込み・ログ確認できる状態にする。
対応：DEV-03〜05、TEST-01。

## 準備

- Macとデータ通信対応のUSBケーブル。
- Waveshare ESP32-S3 4.3BとATOM S3 Lite。
- 公式サンプル、各機器の接続手順。

## 作業手順

1. MacのmacOS版・CPU種別・既存のESP-IDF環境を確認して記録する。
2. Waveshareの4.3B用ESP-IDFサンプルを確認し、対応するESP-IDF版と依存関係を選ぶ。最新版を無条件に採用せず、サンプルとの互換性を優先する。
3. 選んだ版の公式macOS導入手順に沿って、ESP-IDFと必要なツールを導入する。既存環境があれば競合を避けて利用する。
4. ESP-IDFを有効にしたターミナルで `idf.py --version` を実行し、使用中の版を記録する。
5. メイン機・サブ機を別々のESP-IDFプロジェクトとして準備する。両機のチップターゲットはESP32-S3とするが、Flash・PSRAM等の設定は各機器の仕様に合わせる。
6. メイン機は公式サンプル、サブ機は最小構成からビルドする。公式サンプルは原本を残し、作業用コピーを使用する。
7. 機器を1台ずつUSB接続し、接続前後でポートを比較する。Macでは `/dev/cu.*` を確認し、実際のポート名を使用する。
8. 最小構成を書き込み、起動メッセージを確認する。必要な場合だけ各機器の公式手順でダウンロードモードに入る。
9. 同じ手順を両機で確認し、再接続・リセット後にも再実行できる状態を記録する。

## 基本コマンド

ESP-IDF環境を有効にし、対象プロジェクトのディレクトリで実行する。

```sh
idf.py --version
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
```

書き込みとモニターは `idf.py -p <実際のポート名> flash monitor` を使用する。山括弧の部分は説明用であり、そのまま実行しない。
`set-target` は初期設定時に行い、既存サンプルの設定を変更した場合は差分を確認する。

## 問題が起きた場合

| 症状 | 最初に確認する内容 |
| --- | --- |
| ポートが出ない | データ対応ケーブル、Macの接続許可、USB接続先、機器の起動状態 |
| 書き込みできない | 選択ポート、他のモニターによる占有、公式のダウンロードモード手順 |
| ビルドできない | ESP-IDF版、サンプル対応版、依存関係、ターゲット設定 |
| 起動を繰り返す | 給電状態、Flash・PSRAM設定、リセット理由のログ |

USB/CANの同時利用条件は、段階6で実機の配線・公式サンプルと照合する。

## 成果物・完了条件

- [ ] 両機でビルド・書き込み・起動ログ確認ができる。
- [ ] ESP-IDF版、依存関係、ボード設定、ポートの確認方法を記録した。
- [ ] 同じ環境を再現する手順を保存した。

## 公式資料

ESP-IDFはmacOSでの開発に対応する。導入方法は採用版の案内を参照する。[Espressif Get Started](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/get-started/)

メイン機の出発点は4.3B用のサンプルとする。[Waveshare ESP-IDF手順](https://docs.waveshare.com/ESP32-S3-Touch-LCD-4.3B/ESP-IDF)

サブ機のUSB接続・ダウンロード操作は機器の公式資料を参照する。[M5Stack AtomS3-Lite](https://docs.m5stack.com/en/core/AtomS3-Lite)
