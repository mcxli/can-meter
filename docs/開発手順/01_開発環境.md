# 1. Macでの開発環境構築

## 目的・対応要件

Macで両機のRustコード（ESP-IDF上のstd環境）をビルドし、USBで書き込み・ログ確認できる状態にする。
対応：DEV-03〜05、TEST-01。

## 準備

- Macとデータ通信対応のUSBケーブル。
- Waveshare ESP32-S3 4.3BとATOM S3 Lite。
- 公式サンプル、各機器の接続手順。
- Rustの導入方法（rustup）と、ESP32-S3（Xtensa）向けRustツールチェーンの公式手順。

方針：ESP-IDFの上でRustのstd環境（`esp-idf-svc`・`esp-idf-hal`・`esp-idf-sys`）を使う。ESP-IDF本体は、Waveshare公式サンプルと互換性のある版を使う（`esp-idf-sys`のESP-IDF版指定、または`IDF_PATH`で既存のESP-IDFを利用）。Cが必要な部分（LVGL・LCD初期化等）は`esp-idf-sys`経由またはCコンポーネントで併用する。

## 作業手順

1. MacのmacOS版・CPU種別・既存のESP-IDF環境を確認して記録する。
2. Waveshareの4.3B用ESP-IDFサンプルを確認し、対応するESP-IDF版と依存関係を選ぶ。最新版を無条件に採用せず、サンプルとの互換性を優先する。
3. Rust側の前提として、ESP-IDF公式のmacOS前提パッケージ（git、cmake、ninja、python3等）だけをHomebrew等で導入する。`esp-idf-template`の案内では、ESP-IDF本体のクローン・導入・有効化は不要（`esp-idf-sys`がビルド時に取得する）。
4. [rustup](https://rustup.rs)でRustを導入し、次のツールを導入する（コマンドは下の「Rust環境の導入」を参照）。`espup install`でESP32-S3（Xtensa）向けのRust・Clangツールチェーンを導入し、生成された `export-esp.sh` を、ビルドを行う各ターミナルで読み込む。
5. `rustc --version`、`cargo --version`、各ツールの版、ツールチェーンの種別を記録する。Waveshareの公式Cサンプルを確認する場合に限り、別途ESP-IDFを導入して `idf.py --version` で版を記録する（Rust側の環境とは独立）。
6. メイン機・サブ機を別々のCargoプロジェクト（ワークスペース）として準備する。公式テンプレート（`esp-idf-template`）を起点にし、チップターゲットはESP32-S3、Flash・PSRAM等の設定（`sdkconfig.defaults`）は各機器の仕様に合わせる。
7. サブ機は最小構成のRustプロジェクト（ログ出力のみ）をビルドする。メイン機は、同様のRustプロジェクトに加えてWaveshare公式のCサンプルをビルドし、両方が動作する状態にする。公式サンプルは原本を残し、作業用コピーを使用する。
8. 機器を1台ずつUSB接続し、接続前後でポートを比較する。Macでは `/dev/cu.*` を確認し、実際のポート名を使用する。
9. 最小構成を書き込み、起動メッセージを確認する。必要な場合だけ各機器の公式手順でダウンロードモードに入る。
10. 同じ手順を両機で確認し、再接続・リセット後にも再実行できる状態を記録する。

## Rust環境の導入

出典：`esp-rs/esp-idf-template` の Prerequisites、The Rust on ESP Book。導入時点で最新の案内と差がないか確認する。

```sh
# 前提パッケージ（macOS。Homebrewの場合）
brew install cmake ninja python3

# rustup（https://rustup.rs の手順に従う）

# Cargoのサブコマンド
cargo install cargo-generate
cargo install ldproxy
cargo install espup
cargo install espflash

# Xtensa向けRust・Clangツールチェーン
espup install
. $HOME/export-esp.sh
```

`export-esp.sh` の読み込みは、ビルドを行うターミナルごとに必要。案内ではespflashは2.0以上が前提。プロジェクトは `cargo generate esp-rs/esp-idf-template cargo` で生成し、MCUに `esp32s3` を選ぶ。ESP-IDF版は、`IDF_PATH` を設定した場合はその版が優先される。

## 基本コマンド

Rustプロジェクトのディレクトリで実行する。ターゲット名・使用ツールは、テンプレートが生成した`.cargo/config.toml`に従う。

```sh
rustc --version
cargo build
cargo run
```

書き込みは `espflash flash target/xtensa-esp32s3-espidf/debug/<プロジェクト名>` で行う。`--monitor` を付けるとシリアルモニターが開く。ポートを指定しない場合、espflashが検出した一覧から選択できる。実際のポート名は `/dev/cu.*` で確認する。
Cの公式サンプル確認には従来どおり `idf.py -p <実際のポート名> flash monitor` を使用する。山括弧の部分は説明用であり、そのまま実行しない。

## 問題が起きた場合

| 症状 | 最初に確認する内容 |
| --- | --- |
| ポートが出ない | データ対応ケーブル、Macの接続許可、USB接続先、機器の起動状態 |
| 書き込みできない | 選択ポート、他のモニターによる占有、公式のダウンロードモード手順 |
| ビルドできない | Rustツールチェーンの種別、ESP-IDF版（`esp-idf-sys`の指定）、依存クレートの版、ターゲット設定 |
| 起動を繰り返す | 給電状態、Flash・PSRAM設定、リセット理由のログ |

USB/CANの同時利用条件は、段階6で実機の配線・公式サンプルと照合する。

## 成果物・完了条件

- [ ] 両機でビルド・書き込み・起動ログ確認ができる。
- [ ] ESP-IDF版、Rustツールチェーン・各ツールの版、依存クレート（`Cargo.lock`）、ボード設定、ポートの確認方法を記録した。
- [ ] 同じ環境を再現する手順を保存した。

## 公式資料

Rust on ESP-IDFは`esp-rs`が提供する。[esp-idf-svc](https://github.com/esp-rs/esp-idf-svc)、[esp-idf-sys](https://github.com/esp-rs/esp-idf-sys)


ESP-IDFはmacOSでの開発に対応する。導入方法は採用版の案内を参照する。[Espressif Get Started](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/get-started/)

メイン機の出発点は4.3B用のサンプルとする。[Waveshare ESP-IDF手順](https://docs.waveshare.com/ESP32-S3-Touch-LCD-4.3B/ESP-IDF)

サブ機のUSB接続・ダウンロード操作は機器の公式資料を参照する。[M5Stack AtomS3-Lite](https://docs.m5stack.com/en/core/AtomS3-Lite)
